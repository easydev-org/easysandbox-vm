# The official install images, cached in ghcr.
#
# WHY A CACHE
#
# SourceForge served the MX ISO at 967 KB/s on a good day and hung completely on a
# bad one: a run sat on the redirect for fifty-six minutes and its log held one line.
# Releases.ubuntu.com and dl.fedoraproject.org are fine but not always reachable from
# a runner, and every bake downloading a multi-gigabyte image from a stranger's mirror
# is a failure mode repeated once per distribution.
#
# So each image is fetched once, pushed as an OCI layer, and pulled from ghcr - the
# same registry the runner image already comes from, which the workflows authenticate
# to anyway.
#
# FORMAT, one per line: name|url|expected-size
#
# The size is checked after the download. A mirror that serves an HTML error page with
# status 200 is the classic way this goes wrong quietly - the file exists, is tiny, and
# qemu fails much later with something unrelated.
#
# Every URL here was fetched and measured before being written down. Speeds at the
# time, for reference: garuda 3.4 MB/s, pop-os 1.9 MB/s, almalinux 1.9 MB/s, rocky
# 793 KB/s, zorin 612 KB/s (halifax mirror), alpine 906 KB/s, mint 124 KB/s.
#
# Distributions the bakes already handle keep their existing URLs; these are the ones
# that have no bake yet, plus the two that were costing the most time.
